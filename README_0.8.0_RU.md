# AgentBridge 0.8.0 — диалог, условия и виджет

Персональная сборка для проверки (REVIEW), 19 октября 2026.
Пакет `com.pluginslab.agentbridge`, версия `0.8.0-local`, versionCode 30.
Основа — исходники 0.7.0; учтены новые разделы 14–19 карточки проекта и актуальная архитектура. Архив содержит снимок требований `ARCHITECTURE_0.8_INPUT_RU.md` и правила работы `AGENTS.md`.

## Установка

Установите `AgentBridge-0.8.0-dialogue-widget.apk` поверх персональной 0.7.0, не удаляя приложение. Сертификат сохранён; проверено совпадение с предоставленной 0.5.7:
`7c647f03e0bf659557deb182c609ebf6419466b98daa607c793be3a0e068e775`.

Миграция БД добавляет диалог и квоты, сохраняя таблицы памяти и задач. Имена настроек ключей API и Android Keystore alias сохранены. Реальная миграция на устройстве ещё не проверена. При несовпадении подписи установленной версии Android отклонит обновление; удаление приложения сбрасывает его локальные данные.

## Что изменилось

- Один сохранённый диалог для обсуждения и работы. Поле ввода доступно во время задачи, уточнения и ожидания квоты. Вопрос «почему» или «как» обсуждается без команды логически приостанавливать задачу. Явное «новая задача: …» ставит отдельную задачу в очередь; после успешного завершения текущей начинается следующая.
- Изменение условий повышает ревизию задачи. Устаревший ответ модели не может отправить новое Android-действие: проверка ревизии и отправка действия проходят под общей блокировкой. Агент заново читает экран и подтверждает новый план. Уже отправленное системе действие может завершиться; отмены его эффекта нет.
- Локальные «пауза», «продолжить» и «стоп» различаются. Остановка отменяет последующие действия и просроченные ответы; пауза сохраняет возможность продолжения. Команды управления не требуют ответа API. Повторная доставка одной команды не выполняет её повторно.
- Уточнение `WAIT_USER` сохраняет ID вопроса и задачи. Ответ из чата или уведомления относится к тому же вопросу; повторный ответ не создаёт вторую задачу.
- Общая очередь API для рабочих запросов, обсуждения, проверки соединения и повторов. Приоритет диалога, резерв запросов, ограничение серии приоритетных запросов и старение очереди поддерживают продвижение фоновой работы. Все реальные попытки учитываются, включая неудачные запросы и повторы. Серверный cooldown сохраняется и не сокращается более короткой ошибкой.
- Виджет домашнего экрана, уведомление с ответом и компактное окно используют тот же диалог. В настройках есть добавление виджета; также можно добавить его через список виджетов Android. Микрофон открывает компактный диалог с системным распознаванием; закрытие окна не отменяет задачу. Разрешение рисования поверх приложений не требуется.
- Тёмный интерфейс с мягким зелёным акцентом и закреплённым полем ввода. Итог появляется в диалоге один раз, история задач вынесена в журнал. Кнопки управления зависят от состояния.
- Сохранены провайдеры Gemini, OpenAI, Anthropic и совместимый API, память, импорт/экспорт, голос и внешний MCP. Внутренние команды уточнения и ревизии не выставляются внешнему MCP.

Когда пользователь открывает диалог или системную панель поверх рабочего приложения, исполнитель ждёт возвращения целевого экрана. Задача при этом не переводится в пользовательскую паузу; обсуждение доступно. Это предотвращает нажатия по окну самого агента. Для первого открытия приложения из панели агента предусмотрен отдельный путь.

## Квоты

Настройки доступны для выбранного провайдера и модели: проект/аккаунт, группа моделей, RPM, входные TPM, RPD и резерв для диалога. Значение 0 означает неизвестный локальный лимит, а не отсутствие лимитов на стороне сервера. Разные ключи одного проекта не считаются независимыми квотами. Для моделей с общей квотой укажите одинаковую группу.

На основании предоставленного скриншота сохранены редактируемые стартовые значения, только для совпадающих ID моделей:

| Модель | RPM | Входные TPM | RPD |
| --- | ---: | ---: | ---: |
| Gemini 3.5 Flash Lite | 15 | 250000 | 500 |
| Gemini 3.8 Flash | 5 | 250000 | 20 |
| Gemini 3.1 Flash Lite | 15 | 250000 | 500 |

Пики на скриншоте за 28 дней не трактуются как текущее исчерпание квоты. Эти значения не подтверждают доступность модели и не обновляются автоматически. Сверяйте с лимитами своего проекта.

Планировщик использует интервалы между запросами с запасом и скользящие окна. Входные токены сначала резервируются по консервативной оценке UTF-8-байтов, затем уточняются по usage API, когда он доступен. Это оценка, а не точный токенизатор. RPD учитывается за скользящие 24 часа, без предположения о часовом поясе сброса провайдера. Ограничения сервера, Retry-After и дневные ошибки имеют приоритет.

Если запрос не допускается в пределах бюджета ожидания, задача сохраняется как WAIT_QUOTA. После окончания указанного ожидания её можно продолжить. Локальная остановка остаётся доступной. Очередь не координируется с другими устройствами и программами, использующими тот же проект.

## Данные и границы

Сообщения, поля задач и журнал квот сохраняются в зашифрованной БД. В диалоге показываются последние 120 сообщений, сохраняется до 1000. Очистка диалога и очистка журнала — разные действия. Экспорт знаний не включает API-ключи и переписку. Правила доступа памяти к облаку из 0.7 сохранены; текущая задача и её диалог передаются выбранному API для выполнения запросов.

Распознаваемые ключи, токены и пароли маскируются на виджете и в уведомлении. Для произвольных личных данных включите скрытие текста в настройках: автоматическая маска не распознаёт любой секрет.

Классификатор намерений и исполнитель зависят от ответов модели; полная семантическая валидация высокорисковых действий не реализована. Для однозначности используйте явные формулировки: «новая задача: …», «добавь условие: …», «пауза», «продолжить», «стоп». Восстановление после убийства процесса — через сохранённую задачу и свежий экран; автоматического продолжения действий при запуске приложения нет.

Нет синхронизации, непрерывного прослушивания и wake word. Сырой экранный журнал текущего запуска остаётся в оперативной памяти, не превращается автоматически в долговременные знания. Предыдущие ограничения памяти и проверки результата описаны в README_0.7.0_RU.md.

## Проверка на телефоне

1. Установить поверх 0.7, открыть память и настройки: записи и ключи должны сохраниться. Проверить соединение с выбранной моделью.
2. Написать обычный вопрос: получить ответ без Android-действий. Затем дать простую явную задачу чтения экрана.
3. Во время работы спросить «почему ты выбрал этот шаг?»: диалог отвечает, задача не переходит в пользовательскую паузу. Вернуться в целевое приложение для следующих действий.
4. Во время ожидания модели добавить условие. Проверить обновлённую версию/план; старый ответ не должен запускать действия по прежним условиям.
5. Нажать паузу и продолжить. Затем остановить во время запроса/ожидания квоты: поздний ответ не возобновляет действия. После остановки очередь не стартует сама.
6. На задаче с недостающими данными проверить уточнение: ответить через уведомление; убедиться, что продолжается та же задача. Повторно доставленный ответ не запускает её второй раз.
7. Добавить виджет, открыть чат и микрофон. Проверить единые сообщения, вопрос и статус с основным окном; закрытие компактного окна не отменяет работу. Проверить скрытие личного текста.
8. Проверить длинный русский текст, открытую клавиатуру и увеличенный системный шрифт: ввод доступен, итог не дублируется, после завершения нет активной большой кнопки «Стоп».
9. Сверить квоты со своим проектом. При реальном 429 проверить общий cooldown и WAIT_QUOTA, доступность ввода/остановки и продолжение после ожидания. Для теста не требуется намеренно расходовать всю дневную квоту.
10. Перезапустить процесс на паузе, продолжить сохранённую задачу: сначала проверяется текущий экран; неизвестное прошлое действие не повторяется вслепую.

## Сборка из исходников

Установить JDK 17, Android SDK 35 и build-tools 35.0.0. Указать sdk.dir в собственном local.properties либо ANDROID_HOME.

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

Обычные репозитории Google/Maven Central используются по умолчанию. Необязательная переменная AGENTBRIDGE_MAVEN_PROXY предусмотрена для локального зеркала среды сборки. Подписать APK личным ключом отдельно. Ключ подписи, API-ключи, SDK, локальные пути, Gradle-кэши и сборочные каталоги в исходники не включены.
