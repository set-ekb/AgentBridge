# Event Loop Supervisor — первая итерация (25.10.2026)

Статус: REVIEW. На телефоне и в сборке ещё не проверено.

## Почему не отдельный сервис

AgentBridge уже содержит ApiQueue, TaskGate, CheckpointRules,
OpenCodeTaskClient и локальный шлюз Termux. Новый независимый агент
дублировал бы управление и расходовал контекст.

## Что добавлено

`SupervisorPolicy` — чистая детерминированная функция принятия решения.
Она не обращается к LLM, Android UI и сети.

- RUNNING: ограниченный exponential backoff 1–30 секунд.
- DISCONNECTED: через 5 секунд проверять связь; **не отправлять задачу повторно**.
- UNKNOWN: сверить task UUID и журнал шлюза, не делать предположений.
- DONE/FAILED/CANCELLED: однократная обработка результата.

Измерение интервалов должно использовать монотонные часы Android
(`SystemClock.elapsedRealtime()`), а не `System.currentTimeMillis()`.
Отложенные задачи должны переживать пересоздание Activity; для этого
при интеграции нужна постоянная запись task UUID и последнего terminal event.

## Следующий технический шаг

Встроить политику в обработчик опроса `OpenCodeTaskClient.poll`,
сохранив существующий TaskGate, отмену и контрольные точки. Добавить
событийную доставку через уже существующий шлюз Termux, если версия
шлюза поддерживает поток событий; иначе оставить редкий polling.
Запретить автоматический retry для операций с побочными эффектами
до сверки по UUID.

## Проверки перед выпуском

1. RUNNING не порождает LLM-запросы, polling не чаще установленного интервала.
2. Выключенный Termux не превращается в FAILED и не запускает задачу повторно.
3. После восстановления шлюза старый UUID используется для сверки.
4. DONE/FAILED/CANCELLED доставляются однократно.
5. STOP_REQUESTED и отмена продолжают работать.
6. Открытое окно Bridge не блокирует несвязанные действия OpenCode.
7. Android test, debug compile, lint и реальные Termux/MCP испытания обязательны.

Никакого изменения GitHub Actions или автоматического запуска сборки в этом патче.

## Стабилизация lifecycle (SOL 6.1)

- `unknown` и восстановленный `dispatching` сверяются GET-запросами к уже
  сохранённой session. Пустые сообщения и отсутствие busy не доказывают запуск:
  остаётся `unknown`. Повторного `prompt_async` нет.
- Подтверждённые `done/failed/cancelled` вместе с ответом и безопасным reason
  записываются атомарно (fsync файла, replace, fsync каталога). Терминальное
  состояние больше не опрашивает OpenCode и не заменяется отменой.
- Повторный POST с тем же UUID возвращает состояние существующей задачи.
  GET может повторно вернуть тот же результат: это необходимо при потере HTTP
  ответа. Android подавляет повторное сообщение через существующий уникальный
  `task:<UUID>:opencode` и `MemoryStore.addMessage(CONFLICT_IGNORE)`.
- После перезапуска приложения «продолжай» для неопределённой задачи означает
  сверку того же UUID. Автоматической отправки сохранённых задач при init нет.
- Long-poll запрашивает 15 секунд при Android read timeout 25 секунд. Старый
  параметр 20 принимается, но ограничивается 15. Deadline передаётся в захват
  lock и оба upstream-запроса, сетевой timeout каждого не более 6 секунд и
  оставшегося бюджета. Одноразовый timer закрывает конкретный upstream socket
  по абсолютному deadline, включая медленные заголовки/тело, а не только простой
  соединения. Это не фоновый сервис. Сетевая ошибка — 503/UNKNOWN, не новая задача.
  Старый шлюз с 404 на `/wait` переключает Android на GET `/tasks/<UUID>`;
  404 самого UUID не разрешает повторную отправку. Разрыв клиента не отменяет
  задачу и не записывает тело запроса в журнал.

## Только выбранная история → Drive

`scripts/opencode_session_export.py` использует имеющиеся `opencode` и `rclone`.
Сервис, cron, доступ к SQLite и автозапуск OpenCode не добавляются.

1. `python scripts/opencode_session_export.py --list` — штатный
   `opencode session list --format json`, на экран только ID.
2. Владелец выбирает **точный собственный** ID:
   `python scripts/opencode_session_export.py --session-id ses_EXACT --review-file /private/path/review.json`.
   Используется `opencode export ses_EXACT`; в снимок попадают только текстовые
   user/assistant сообщения. Tool outputs, reasoning, вложения, заголовки и
   метаданные не экспортируются. Файл создаётся эксклюзивно с правами 0600.
3. Просмотреть локальный файл на конфиденциальные данные и скопировать
   напечатанный SHA-256. Затем:
   `python scripts/opencode_session_export.py --session-id ses_EXACT --upload --approved-sha256 EXACT_HASH`.
   Изменившаяся история требует нового просмотра и хеша. Поиск известных
   шаблонов ключей блокирует выгрузку, но не заменяет проверку владельцем.
4. Снимки: `gdrive:00_AI_Context/40_AI_Results/OpenCode_Sessions/`, UTC + UUID
   в имени, `rclone copyto --immutable`, затем проверка `lsf`. Нет sync/delete
   и постоянного файла «latest». Ошибки CLI не печатают сырой stderr/историю.

Периодический режим **выключен по умолчанию**. `--interval 300` запускает его
только в текущем foreground-процессе; Ctrl-C выключает. При фиксированном
`--approved-sha256` изменение истории останавливает экспорт до нового просмотра.
Для автоматического экспорта изменяющегося текста владелец может явно добавить
`--allow-private-history`: это допуск передачи конфиденциальной текстовой истории
именно выбранной сессии; известные ключи всё равно блокируются. Полные raw-дампы
не выгружаются ни в одном режиме. Чужие/все/latest сессии не выбираются автоматически.

Локальные проверки: `python -m unittest discover -s scripts -p 'test_opencode*.py'`.
Android-проверки отдельно: `./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug`.
Не считать Python-тесты доказательством состояния установленного APK.
