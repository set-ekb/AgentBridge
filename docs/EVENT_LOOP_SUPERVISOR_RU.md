# Event Loop Supervisor — первая итерация (25.10.2026)

Статус: REVIEW. На телефоне и в сборке ещё не проверено.

## Почему не отдельный сервис

AgentBridge уже содержит ApiQueue, TaskGate, CheckpointRules,
OpenCodeTaskClient и локальный шлюз Termux. Новый независимый агент
дублировал бы управление и расходовал контекст.

## Что добавлено

`SupervisorPolicy` — чистая детерминированная функция принятия решения.
Она не обращается к LLM, Android UI и сети.

- RUNNING: ограниченный exponential backoff 1–30 секунд.
- DISCONNECTED: через 5 секунд проверять связь; **не отправлять задачу повторно**.
- UNKNOWN: сверить task UUID и журнал шлюза, не делать предположений.
- DONE/FAILED/CANCELLED: однократная обработка результата.

Измерение интервалов должно использовать монотонные часы Android
(`SystemClock.elapsedRealtime()`), а не `System.currentTimeMillis()`.
Отложенные задачи должны переживать пересоздание Activity; для этого
при интеграции нужна постоянная запись task UUID и последнего terminal event.

## Следующий технический шаг

Встроить политику в обработчик опроса `OpenCodeTaskClient.poll`,
сохранив существующий TaskGate, отмену и контрольные точки. Добавить
событийную доставку через уже существующий шлюз Termux, если версия
шлюза поддерживает поток событий; иначе оставить редкий polling.
Запретить автоматический retry для операций с побочными эффектами
до сверки по UUID.

## Проверки перед выпуском

1. RUNNING не порождает LLM-запросы, polling не чаще установленного интервала.
2. Выключенный Termux не превращается в FAILED и не запускает задачу повторно.
3. После восстановления шлюза старый UUID используется для сверки.
4. DONE/FAILED/CANCELLED доставляются однократно.
5. STOP_REQUESTED и отмена продолжают работать.
6. Открытое окно Bridge не блокирует несвязанные действия OpenCode.
7. Android test, debug compile, lint и реальные Termux/MCP испытания обязательны.

Никакого изменения GitHub Actions или автоматического запуска сборки в этом патче.
