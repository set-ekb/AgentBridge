# AgentBridge — переосмысление архитектуры и безопасная оптимизация

Дата: 25.10.2026. Основа: ветка `fix/sol61-supervisor-stabilization-20261025` (коммит `54aa166eca19ca172f33f65e206b38b31bfc7e27`).
Статус: **код для ревью; APK и устройство ещё не проверены**. Не путать с готовым релизом.

## Центральная идея

AgentBridge — контроллер действий и памяти, а не конкретная LLM.
OpenCode, Gemini, Claude и другие — сменяемые исполнители. Важнейшие гарантии
принадлежат контроллеру: кто запросил действие, что подтвердил инструмент,
какой UUID задачи сохраняется и кто разрешил её остановить.

Ниже различаются **подтверждённые наблюдения в исходниках**, **внесённые правки**
и **следующие задачи**, требующие отдельных изменений/проверок.

## 1. Пять точек зрения

| Угол | Подтверждено в исходниках | Вывод |
|---|---|---|
| Владелец, UX | Состояние Android-агента и OpenCode отображается общим виджетом/уведомлением. | Пауза наблюдения не должна выглядеть как остановка задания. |
| Исполнитель/надёжность | `localPause`, `localCancel`, `shutdown` отменяли наблюдающие jobs; обработчик CancellationException делал удалённый abort. | Разнести явную отмену и завершение локального наблюдения; сохранить UUID и результат. |
| Безопасность/приватность | OpenCode получал одобренную память **и** неклассифицированный текст недавнего разговора. | Передавать только текущий запрос и выбранные подтверждённые `cloudAllowed && !isPrivate` записи памяти. |
| Производительность/энергия | Проверка возвращения целевого экрана выполнялась каждые 200 мс, пока поверх открыт AgentBridge. | Постепенно увеличивать задержку до 2 с без LLM-проверок и без повторных действий. |
| Интеграции/переносимость | Есть локальный Gateway 4097, MCP, отдельные Python-тесты и rclone-экспорт. | Не создавать второй task bus или память; дополнять существующие точки. |

## 2. Изменения в этой ветке

1. **Жизненный цикл OpenCode**. Введено правило `OpenCodeLifecyclePolicy`: только явное
   `OWNER_STOP` допускает `abort`. Пауза, выход из интерфейса и закрытие сервиса
   останавливают наблюдение, но не удалённую задачу. Восстановление происходит через
   GET прежнего UUID, а не повторный POST.
2. **Остановка без активного наблюдателя**. После перезапуска приложения явная
   команда `стоп` отправляет abort сохранённому UUID через существующий Gateway;
   подтверждённый ответ сохраняется. При сетевой ошибке — `STOP_UNCONFIRMED`,
   не ложный `CANCELLED`.
3. **Продолжение после перезапуска**. Для любого незавершённого статуса OpenCode
   `продолжай` возвращает задачу к OpenCode, а не передаёт `RUNNING` в Android-runtime.
   Очередная задача `QUEUED` ещё может быть отправлена; остальные — только сверка.
4. **Защита терминальных результатов**. Запоздавшее наблюдение не может изменить
   `COMPLETE/FAILED/CANCELLED` на `RUNNING`; `STOP_REQUESTED` также не затирается
   промежуточным `RUNNING`.
5. **Приватность контекста**. `OpenCodePromptPolicy` строит промпт только из
   поручения владельца и отобранной памяти. Не отправляет всю историю диалога.
   `cloudAllowed`, `verification=confirmed` и `isPrivate` остаются обязательными
   для записей (фильтр `MemoryRules.select`).
6. **Правдивые контролы**. Уведомление не предлагает `Продолжить` при уже активном
   наблюдении OpenCode. Виджет не предлагает бессмысленное `ДАЛЕЕ`; при включённой
   приватности скрывает также фазу задачи.
7. **Умеренный фон**. Цикл ожидания целевого окна использует 200 мс сначала, 750 мс
   после 3 с, 2 с после 15 с. Это не модельный опрос. Время реакции при долгом
   ожидании может увеличиться до ~2 с.

Проверки правил: `OpenCodeSafetyPolicyTest` и обновлённый
`ForegroundWaitRulesTest`. См. отдельные критерии Android-приёмки ниже.

## 3. Что принципиально НЕ вводим

- Второй брокер задач, параллельную базу памяти или новый постоянно работающий LLM-supervisor.
- Автоматический повтор промпта после неопределённого статуса.
- Фоновую запись микрофона / wake-word без отдельного явного выбора владельца.
- Скрытые нажатия по UI в собственной панели AgentBridge.
- Неявный root, автоматическое отключение системных приложений или изменение VPN.
- Публикацию сырых логов и ключей в публичный репозиторий.

## 4. Открытые проблемы: приоритеты

**P0. Периметр MCP.** `KtorServer.start` сейчас привязывается к `0.0.0.0`;
по сети HTTP передаются Bearer-токены. Маршруты проверяют ключи, но это
не равнозначно шифрованию канала. Следующая итерация: local-only по умолчанию
для нового подключения, явное включение LAN с предупреждением,
не нарушая уже настроенный внешний доступ без миграционного плана.
Не меняем bind здесь без проверки сетевых сценариев на устройстве.

**P0. End-to-end проверка stop/pause/shutdown.** Фактическое поведение зависит
от Android lifecycle и OpenCode версии 1.19.3. Нужны инструментальные тесты
с отключением сети между принятием запроса и подтверждением, kill процесса,
foreground/background, активной собственной панелью и Termux restart.

**P1. Управление голосом.** Обеспечить полудуплексный режим «нажми — скажи —
получи проверенный ответ», без непрерывного прослушивания. Состояние
микрофона и вывода голосом не должно маскировать незавершённую задачу.

**P1. Экспорт OpenCode всех сессий.** Владелец подтвердил полный экспорт.
Уже работающий экспортёр сессий на Termux — единственный механизм публикации
через `rclone`; не заводить второй. Для снижения CPU/I/O использовать
`opencode session list --format json` и `time.updated` как быстрый фильтр,
после экспорта — SHA-256, а `--immutable` — защита от перезаписи. Сетевой
DNS-сбой считать временным. Отдельно заменить устаревающий общий OAuth client_id
rclone на собственный без раскрытия ключей в отчёте.

**P1. Политики и доказательства.** Разделять `tool call accepted`,
`effect verified`, `UNKNOWN` и `FAILED`. Не давать сообщению модели/тексту
веб-страницы подменять согласие владельца. Существующий `TaskGate` и
`UiContextPolicy` не переносить внутрь API провайдера.

**P2. Поддерживаемость.** Большие `ConversationHub.kt`, `PanelActivity.kt`
и `ToolRegistry.kt` заслуживают поэтапного разделения по границам
контроллер / UI / действия; исключительно после снимка тестового покрытия,
а не за счёт механического дробления файлов.

## 5. Проверки перед APK

1. `python -m unittest discover -s scripts -p 'test_opencode*.py'`.
2. `./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug`
   (JDK 17, Android SDK 35, Gradle wrapper 8.9).
3. На устройстве: начать OpenCode, открыть панель AgentBridge, уйти в другое
   приложение и убедиться, что работа продолжается; затем «пауза» и проверка,
   что prompt не перезапускался и abort не вызывался.
4. «Стоп» в активном состоянии и после перезапуска: убедиться в сетевом
   подтверждении. При недоступном Gateway должно остаться `STOP_UNCONFIRMED`.
5. При потере ответа/ACK: UUID сохраняется, no duplicate POST, `UNKNOWN` не
   объявляется успехом. `done` отображается единожды.
6. В OpenCode не передаётся закрытая память и недавние сообщения, не
   относящиеся к поручению; проверка логов без настоящих ключей.
7. Виджет/уведомление: реальная роль кнопок, скрытая фаза при приватном
   режиме, а также крупный шрифт и заблокированный экран.

**Не выполнено этой итерацией:** полноценная Android-сборка, тесты на телефоне,
сквозные MCP/Termux/голосовые испытания и проверка безопасности LAN.
`main`, подпись APK, GitHub Actions, релизы и пользовательские настройки
не менялись.
