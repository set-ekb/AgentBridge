# AgentBridge 0.8.6 — локальная аналитика и экран «Состояние»

**Статус:** реализованы шесть инструментов *только для чтения*, диагностический анализатор,
экран состояния и начальные непрозрачные корреляционные ID. Полная автоматическая
восстановительная логика/трассировка UI до подтверждённого результата пока **не реализована**.

## Инструменты для встроенного агента и внешнего MCP

Инструменты работают через общий `ToolRegistry` → `LocalTools`, одинаково для
Gemini, OpenAI, Anthropic и совместимых провайдеров. Никаких дополнительных API
или токенов для анализа не требуется.

| Инструмент | Что возвращает |
| --- | --- |
| `get_diagnostics_summary` | Количество наблюдавшихся событий и задач, категории исходов, ошибки, доступное покрытие. |
| `get_recent_errors` | Группы ошибок с частотой и временем последнего появления (лимит категорий). |
| `check_bridge_health` | Подключена ли Accessibility, есть ли журнал, выполняется ли задача; состояние Vector и провайдеров честно помечено неизвестным, если не проверялось. |
| `analyze_api_failures` | Количество наблюдавшихся запросов/ответов/ошибок, категории 429/503/exception, p50/p95 времени успешных ответов. |
| `analyze_tool_performance` | p50/p95 длительности, успешные ответы, ошибки/отклонения на уровне **инструмента**, не пользовательской задачи. |
| `inspect_hook_pipeline` | Наличие сигналов Accessibility / receiver / Xposed hints и неопределённые стадии загрузки внутри Vector. |

Каждый инструмент принимает необязательный `hours` от 1 до 72 (по умолчанию 24).
`get_recent_errors` также принимает `limit` от 1 до 30. Невалидные/слишком
большие числа ограничиваются. В анализ попадают максимум 1800 последних строк JSONL.

**Возможное ограничение:** текущий журнал размером до 768 КБ ротируется и
не содержит всю историю, поэтому `errors_observed=0` **не означает** отсутствия
ошибок за выбранный период. `historical_completeness` всегда `unknown`.
При пустом журнале `overall=unknown`. Отсутствие Vector-событий возвращает
`unknown_optional` или `not_observed`, не `failed`.

## Состояние

Пятая вкладка **«Состояние»** отображает локальную сводку по нажатию кнопки
**«Проверить состояние»**: Connectivity Accessibility, статус журнала,
неподтверждённые события Vector, активность агента, число наблюдавшихся
технических ошибок и качество доступных свидетельств. Выполняется локально и
не отправляет сетевые запросы модели. Полная экспортируемая диагностика
остаётся во вкладке **«Журнал»**.

## Безопасность и ограничения

- Анализатор получает **только уже очищенные технические записи** из `Diagnostics`.
  Сырые тексты задач, экранов, аргументов вызовов, API ключи и HTTP тела
  в него не поступают. Нестандартные поля JSON игнорируются.
- У `Diagnostics` появились необязательные `attempt_id` и `action_id`,
  генерируемые как UUID при запуске задачи и при инструментальном вызове.
  Они не содержат текст задачи и пригодятся для будущего полного трейсинга.
  Корреляция с конкретным UI переходом пока не гарантируется.
- Не исполняется `su`, `logcat`, системные команды или автоматическое исправление;
  внешние `vector_hint` считаются недоверенными подсказками.
- Сообщение `tool_finish=ok` означает ответ инструмента, а не успех задачи.
  Отсутствующие сведения обозначаются `unknown` / `not_checked`.
- Агрегация детерминированная и доступна без вызова LLM. Модель объясняет
  результат только при явной задаче или диагностике собственной ошибки.

## Проверка на реальном Android

1. Обновить APK **поверх** версии 0.8.5 тем же сертификатом.
2. Открыть «Состояние» и нажать «Проверить состояние». Проверить наличие
   событий в журнале и верный статус Accessibility; неизвестные статусы не
   должны превращаться в ложные «зелёные».
3. Встроенному агенту дать задачу: «Проверь свою диагностику за последний час,
   не изменяй настройки». Проверить, что использован один из шести инструментов
   и ответ не содержит личные данные.
4. Проверить пустой/ротированный журнал, ошибку модели 429 и неуспешное
   действие: количество событий, категории и причинные связи не выдумываются.
5. При включённом Vector сравнить `inspect_hook_pipeline` с реальным экраном
   Vector → Журналы. Отсутствие записи из Vector не трактовать как падение модуля.

Оставшиеся задачи анализа циклов, регрессий, полного `trace_task` и
предлагаемых планов восстановления — в
[Roadmap Issue #3](https://github.com/set-ekb/AgentBridge/issues/3).
