# Запуск OpenCode и коннектора из AgentBridge 0.8.12

В настройках OpenCode появилась кнопка «Запустить OpenCode и коннектор».
Она отправляет в Termux фиксированную команду запуска `opencode_start.py`.
Пароль OpenCode и ключ сопряжения читаются внутри Termux, в intent их нет.
Запуск не отправляет запросы модели и не возобновляет прежние задачи.

## Подготовка один раз

В `~/projects/agentbridge-opencode/` должны находиться файлы из одной версии:

- `opencode_start.py`;
- `opencode_bridge_gateway.py`;
- `opencode_task_bridge.py`;
- `opencode_mcp_profile.json`.

В Termux должны быть установлены Python и OpenCode. Используется прежний пароль
из `~/.config/agentbridge-opencode/password` (права 0600). Ключ сопряжения
`~/.config/agentbridge-opencode/pairing-token` сохраняется прежним; если его ещё
нет, первый ручной запуск создаст его. Введите этот ключ в настройках Bridge.
Не публикуйте содержимое этих файлов.

Для первой проверки можно выполнить в Termux:

```bash
python "$HOME/projects/agentbridge-opencode/opencode_start.py" --enable-tasks --supervise
```

Для кнопки дополнительно требуется разрешить AgentBridge «Запуск команд в
Termux» в разрешениях Android и установить `allow-external-apps=true` в
`~/.termux/termux.properties`, затем применить настройки Termux. Это даёт
приложению возможность запускать команды с правами Termux, а не только проверять
состояние. Bridge использует его только для фиксированной кнопки, не для текста
модели. Можно отозвать разрешение Android, сохранив ручной запуск.
Официальный протокол: https://github.com/termux/termux-app/wiki/RUN_COMMAND-Intent

## Поведение

- Кнопка запускает OpenCode на 127.0.0.1:4096 и шлюз на 127.0.0.1:4097.
- Новый OpenCode получает отдельный MCP-профиль с Android MCP, старый основной
  конфиг не переписывается. Шлюз допускает задания через существующую явную кнопку
  «Выполнить через OpenCode». Собственные разрешения OpenCode сохраняют силу.
- Повторное нажатие не создаёт дубликаты: запуск защищён межпроцессной блокировкой,
  работающие сервисы проверяются по авторизованным health/status запросам.
- При запуске кнопкой управляющая команда остаётся активной в Termux. Она не
  перезапускает процессы и задачи автоматически; ограничения Android на фоновые
  процессы всё равно могут остановить Termux. Выход из Termux может оборвать связь.
- Чужой/непроверенный процесс на занятом порту не завершается. Ошибка запуска
  убирает только процессы, созданные именно этой попыткой.
- Уже работающий OpenCode переиспользуется: его конфигурация MCP не меняется.
  Старый шлюз в режиме только чтения также не переводится автоматически в режим
  заданий. Если нужно сменить режим, завершите его вручную после окончания задач.
- Статус «коннектор доступен» подтверждает только доступность OpenCode через шлюз.
  Работу Android MCP проверяйте отдельно при запущенном MCP-сервере Bridge (:8080).
- После перезагрузки нажмите кнопку снова. Автозапуск при загрузке и перезапуск
  оборванных задач в эту итерацию не входят.
- Если готовность не подтверждается, проверьте Termux и приватные файлы
  `~/.config/agentbridge-opencode/opencode-startup.log` и `gateway-startup.log`.
  Приложение не получает вывод команд и секреты.

## Проверки

15 Python-тестов OpenCode проходят, включая 7 новых проверок запуска: повторное
использование, параметры и секреты, режим заданий, занятые порты, уборка только
новых процессов, права секретов и конкурентный запуск.
Android-компиляция и проверка кнопки на реальном телефоне фиксируются отдельно;
не считать доставку intent доказательством запуска. Текущий код ждёт успешный
авторизованный ответ шлюза.
