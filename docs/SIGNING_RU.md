# Постоянная подпись и прямая ссылка на AgentBridge APK

## Зачем

Ранее каждая сборка GitHub Actions получала собственный временный debug-keystore.
Например, сертификат APK 0.8.1 имеет SHA-256
`EC8DE6B4419E09B867062C251E6A2970E869DC6D2D1AAB30CC6DC40B8EF34FBF`,
а APK 0.8.2 —
`B8D478788B56E2A22A1591C4CD3BFCDA6E5E3F57D33E9817B8A92D3CBD116575`.
Поэтому Android отвергает обновление старой версии на новую.

Подписывание исправлено следующим образом:

- ПКCS#12 с единственным постоянным сертификатом и alias `agentbridge`.
- Закрытый ключ хранится только у владельца и как зашифрованный GitHub Actions secret.
- SHA-256 сертификата закрепляется отдельным secret, чтобы случайная замена ключа
  приводила к ошибке сборки, **а не** к публикации APK с новой подписью.
- При отсутствии секретов workflow выполняет только тесты и debug-компиляцию,
  но **не публикует временно подписанные APK**.
- Подписанные `release` APK выкладываются в GitHub Releases,
  без необходимости вручную извлекать файл из архива Actions.
- Скрипт `scripts/setup-signing.sh` никогда не перегенерирует существующий локальный ключ.

## Настроить один раз

Требуются `JDK 17` (команда `keytool`), `gh` (GitHub CLI),
`base64`. В Termux подходят пакеты `openjdk-17` и `gh`
(если доступны в текущих репозиториях).

Авторизуйтесь в GitHub CLI и запустите **локально**:

```bash
gh auth login
bash scripts/setup-signing.sh
```

Скрипт создаёт `~/.config/agentbridge/signing/agentbridge-release.p12`
или использует существующий файл; спрашивает пароль; устанавливает
три секретных значения в GitHub Actions и запускает workflow:

- `AGENTBRIDGE_SIGNING_KEYSTORE_B64` — base64-байты закрытого PKCS#12.
- `AGENTBRIDGE_SIGNING_PASSWORD` — пароль к контейнеру и ключу.
- `AGENTBRIDGE_SIGNING_CERT_SHA256` — отпечаток X.509 сертификата (без двоеточий).

Все последующие выпуски необходимо подписывать **этим же ключом**.
Потеря ключа и его пароля может сделать дальнейшие обновления невозможными.

## Постоянные ссылки

Доступны после первого успешно подписанного GitHub Release:

- Основной APK: https://github.com/set-ekb/AgentBridge/releases/latest/download/AgentBridge.apk
- Опциональный Vector APK: https://github.com/set-ekb/AgentBridge/releases/latest/download/AgentBridge-Hooks.apk

GitHub Releases отдают конкретные APK, а не ZIP-архивы GitHub Actions.
Имя файла одинаковое для всех выпусков; номер версии повышается в Gradle.

## Первый переход со старой debug-подписи

Для **одной** миграции с 0.8.1/0.8.2 может потребоваться удаление старой
установки, поскольку прежнего закрытого ключа нет. Нельзя просто «выключить»
проверку сертификата Android без вмешательства в безопасность системы.

**Сначала** в прежнем AgentBridge экспортируйте доступные данные памяти,
сохраните нужные настройки, проверьте резервную копию; при удалении приложения
ключи API и некоторые данные могут быть утрачены. Снова введите API-ключи после
установки подписанного выпуска.

Если оригинальный debug-keystore всё-таки доступен, можно использовать **его**
вместо создания нового, но тогда проверьте, что он содержит alias `agentbridge`
или адаптируйте конфигурацию до перехода.

## Проверки CI

После подписывания проверяются APK Signature Scheme и минимальный Android SDK,
а отпечаток сравнивается с закреплённым секретом. GitHub Actions не сохраняют
приватный ключ в репозитории и удаляют временный keystore после сборки.
