# OpenCode + AgentBridge: собственные инструменты и Android MCP

## Решение

OpenCode остаётся полноценным агентом Termux: использует свои инструменты для
исследования файлов, кода, Git, терминала и других MCP-серверов. Мы **не**
переписываем инструменты OpenCode под `AgentRuntime`.

AgentBridge предоставляет дополнительный **ограниченный** MCP-интерфейс
`http://127.0.0.1:8080/mcp/opencode`. В первой итерации только чтение:
`get_active_window_info`, `get_ui_tree`, `find_nodes`, `list_apps`
и шесть агрегированных диагностических инструментов.

Текущее приложение по-прежнему имеет полный MCP на `/mcp` для существующих
пользовательских клиентов. Ключ сопряжения OpenCode **не может** авторизоваться
в полном MCP: он работает лишь на отдельном пути. Полный MCP и его Bearer
не передавать OpenCode. Отсутствующий/отозванный ключ сопряжения запрещает
доступ к ограниченному пути.

**Внимание:** содержимое экрана может включать приватный текст. Подключай
OpenCode к экрану только осознанно. Встроенные инструменты OpenCode выполняются
с правами процесса Termux. Безопасность Android-инструментов Bridge не ограничивает
встроенный bash/edit OpenCode или потенциальные возможности root/внешних MCP.
Настраивай разрешения OpenCode независимо и не предоставляй shell/правки
бесконтрольно. `ask` может потребовать открытый интерфейс OpenCode для одобрения.

## Настройка (после выпуска APK с ограниченным MCP)

1. Установить совместимый подписанный APK поверх текущей версии; сохранить память
   и настройки. В настройках AgentBridge уже должен быть сохранён отдельный
   ключ сопряжения с OpenCode (тот же, что используется шлюзом :4097).
2. Убедиться, что включён MCP-сервис AgentBridge на порту 8080. При
   нестандартном порте изменить URL в шаблоне.
3. Установить `OPENCODE_CONFIG` на путь к **отдельному** конфигу, созданному
   из `scripts/opencode_mcp_profile.json`, не затрагивая основной opencode.json.
   В примере ключ подставляется из переменной окружения, а не записан в git.
4. Запускать сервер OpenCode с `AGENTBRIDGE_MCP_TOKEN` из файла
   `~/.config/agentbridge-opencode/pairing-token` и `OPENCODE_CONFIG`;
   старый процесс без этой конфигурации надо корректно остановить.
   Не печатать переменную/ключ в логи, не отправлять ключи в чат.

Пример запуска в Termux (свой пароль OpenCode хранится отдельно):

```bash
export AGENTBRIDGE_MCP_TOKEN="$(cat "$HOME/.config/agentbridge-opencode/pairing-token")"
export OPENCODE_CONFIG="$HOME/projects/agentbridge-opencode/opencode_mcp_profile.json"
export OPENCODE_SERVER_PASSWORD="$(cat "$HOME/.config/agentbridge-opencode/password")"
opencode serve --hostname 127.0.0.1 --port 4096
```

Сначала скопировать шаблон `scripts/opencode_mcp_profile.json` в путь
`OPENCODE_CONFIG` (без изменения основного конфига), установить права
`chmod 600`. Не перезапускай OpenCode, пока новый APK не установлен.

## Ограничения этого этапа

- Подключение MCP **не** означает пересылку задач из интерфейса AgentBridge в OpenCode.
  Для этого потребуется отдельный двунаправленный адаптер с отправкой задачи,
  получением событий/результатов, паузой/отменой и включением в общую память.
- OpenCode на своём MCP-пути пока не получает Android-действий (нажатия,
  текст, вызовы приложений, уведомления, cookies, JS и т. п.).
- Предстоит проверить на реальном Android: Ktor MCP routing, запуск MCP-сервиса,
  токены по двум путям, доступность из Termux. Не объявлять компонент готовым
  к установке до тестов GitHub Actions и отдельного подписанного релиза.


## Этап обмена заданиями (экспериментальный, без выпуска APK)

Теперь `AgentBridge` может **явно** поручить работу OpenCode кнопкой
«Выполнить через OpenCode · Termux» на странице разговора.

- При отправке `ConversationHub` сохраняет поручение и UUID задачи в
  существующей шифрованной базе `agent_memory.db`; никакой второй истории.
- В Termux шлюз выделяет отдельную сессию OpenCode по UUID. Сопоставление
  UUID → ID сессии сохраняется в `~/.config/agentbridge-opencode/tasks/`
  с правами 0600. Если ответ о отправке потерян, не отправляет повторно.
- Bridge опрашивает результат, дописывает ответ в существующий диалог,
  отмечает `COMPLETE`; отсутствие достоверного подтверждения отмечает
  `UNKNOWN`. Это не доказательство успеха действий внутри OpenCode.
- Кнопка «Стоп» запрашивает `/session/{id}/abort`. При отсутствии
  подтверждения отображается `STOP_UNCONFIRMED`, а не фиктивный успех.
- При старте включаются только выбранные, подтверждённые,
  неотмеченные private и разрешённые для передачи в облако записи памяти.
  OpenCode может работать с внешней моделью, поэтому «локальный» адрес
  Termux сам по себе не означает, что все сведения останутся на телефоне.

**Изменение безопасности:** шлюз по умолчанию остаётся только для
проверки статуса. Для разрешения запуска заданий владелец **явно**
перезапускает шлюз с `--enable-tasks`. Сохранённый ключ сопряжения
после этого разрешает инициировать работу OpenCode, поэтому при
подозрении на компрометацию ключ следует заменить.

После установки соответствующего *нового подписанного APK* и отдельной
проверки на телефоне обновить в Termux оба файла
`scripts/opencode_bridge_gateway.py` и `scripts/opencode_task_bridge.py`,
из той же ветки/релиза. Старый gateway необходимо корректно остановить,
не трогая отдельный процесс OpenCode на 4096. Затем:

```bash
python "$HOME/projects/agentbridge-opencode/opencode_bridge_gateway.py" --enable-tasks
```

Для первого прогона использовать **безвредное** поручение:
«Напиши одну фразу и ничего не меняй». Проверить сохранение одного
ответа в общей истории и отсутствие повторного запуска.
Только после успешного прогона испытывать `Стоп`; не удалять файлы
сессий и не менять системные настройки во время проверки.

### Открытые задачи тестирования

- Python unittest `scripts/test_opencode_gateway.py` и
  `scripts/test_opencode_task_bridge.py` запускать отдельно: текущий
  GitHub Actions workflow тестирует Android/JVM, не Python.
- Реальное OpenCode 1.19.3 API: асинхронный prompt, готовность assistant
  message, статусы busy/idle и abort.
- Android при переходе в фон, Doze и рестарте процесса: статус
  `UNKNOWN` безопаснее повторного выполнения.
- MCP-проверки двух токенов и реально доступного набора инструментов.
- Перед началом работы с файлами настроить разрешения OpenCode и
  сохранить резервную копию важных данных. `AGENTBRIDGE_MCP_TOKEN` не
  предоставлять никакому стороннему сервису.


## Расширение Android-инструментов (ветка feature/opencode-android-actions)

OpenCode **сохраняет штатные** bash/read/edit/Git/web tools. Дополнительный
`agentbridge_android` MCP на `/mcp/opencode` предоставляет ограниченный
набор Android-инструментов: сведения об окне и дереве UI, поиск узлов и
приложений, диагностику, снимок экрана, запуск приложения, открытие URL,
навигационные действия, нажатия, жесты, ввод и очистку текста,
ожидание элементов и окон, уведомления и просмотр страницы браузера.

Владелец не передаёт OpenCode основной Bearer-ключ `/mcp`.
`run_script`, `send_intent`, `browser_eval`, управление cookies и запись
в буфер обмена **не входят** в этот дополнительный Android MCP.
Это не ограничивает собственный bash OpenCode: если Termux имеет root,
OpenCode потенциально может пользоваться им через терминал.
Рекомендуется держать доступ к root закрытым, защищать ключ сопряжения
и внимательно относиться к сторонним репозиториям/промптам.

Обновление MCP требует установки **сборки APK, собранной именно из этой
ветки или её последующего слияния**. Один JSON-профиль на Termux
не добавит отсутствующие инструменты на стороне старого APK.

После установки совместимого APK, включения MCP на :8080 и записи
`opencode_mcp_profile.json` настройте переменные
`OPENCODE_CONFIG`, `AGENTBRIDGE_MCP_TOKEN`, `OPENCODE_SERVER_PASSWORD`
до запуска сервера OpenCode (см. пример выше). Проверяйте MCP через
штатную команду `opencode mcp list` в новом сеансе Termux.
Не публикуйте токены в журнале или скриншотах.
